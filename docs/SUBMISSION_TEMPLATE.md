## 1. LLM Wiki 主題與簡短介紹
我的主題是「AI 如何辨識網路釣魚與詐騙訊息？」。這份 Wiki 以初學者為對象，整理網路釣魚的定義、假網站、可疑訊息、AI 輔助分析的限制與防範方法。我選用六篇官方資料，包含 NIST（2 篇）、FTC、Google、Microsoft 和 FBI。每篇資料整理為摘要、兩個知識點、來源連結與關鍵字，總計產生 18 個可檢索片段。此作品是本地來源導向 Wiki 原型，不是透過雲端 LLM API 自動生成的 Wiki。

## 4. Loop / Graph 設計
討論範圍與教學對象 → 取得至少五篇可信資料 → Ingest（來源摘要、關鍵字、片段）→ 查詢 Wiki / 規劃簡報 → 檢查正確性、易讀性與來源對照 → 產生 HTML → 介面檢查。

Loop 有三處：(1) 資料不夠或不可信，返回取得與整理；(2) 重點超出來源支持，返回 Wiki 整理並重新產生簡報；(3) HTML 操作不正常，返回介面生成。採用這種設計是為了讓每個教學主張可追溯，並避免最後才發現知識錯誤。

## 6. 反思與調整
我認為最容易出現問題的是「Wiki 整理內容 → 生成簡報」節點，因為容易把輔助偵測說成百分之百準確，或把來源沒有證明的推論寫成結論。因此，我把來源檢查往前移到 ingest 階段：每個段落先綁定來源 ID，簡報生成前再次核對引用是否存在，然後才產生 HTML。與原本「生成完才一次檢查」的線性流程相比，這個 Graph 增加了來源校驗與回修 loop，能降低重做成本。

※ 上述「最容易出錯」屬於設計中辨識的主要風險節點，並非多次 LLM API 執行後得到的錯誤頻率統計。若課堂必須提交實際 LLM 生成的失敗案例，需自行補上一筆模型執行前後比較紀錄。
