2. 哪些地方會重跑？

來源 loop

來源不可靠、URL 失效或重點沒有對應出處時，回到來源取得／整理節點。

內容 loop

簡報宣稱超出 Wiki、用語誤導或初學者看不懂時，先修改 Wiki 條目再重新產生該頁。

介面 loop

按鈕失效、投影片太擠或手機版排版溢出時，回到 HTML 結構與樣式節點修正。

4. 反思與修改

最容易出錯的節點：「整理重點 → 轉成簡報」的過程容易把推論說成確定事實，例如將「安全工具能攔截已知釣魚網站」過度簡化成「能辨識所有詐騙」。這是本作品最主要的風險節點，並非聲稱曾有 LLM 執行失敗次數統計。

檢查前移：不等 HTML 完成才檢查；改在③ ingest 建立每個重點的來源 ID，⑤ 審稿時要求投影片必須具有來源 ID、釐清「可能」與「一定」的差別，再進入 HTML 生成。

Workflow 調整：原流程「取得資料 → 摘要 → 產生簡報 → 最後查錯」改為「取得資料 → 有來源 ID 的 Wiki → 逐頁對照檢查 → 產生簡報 → 介面測試」。先消除知識錯誤，能減少後續重做畫面。
